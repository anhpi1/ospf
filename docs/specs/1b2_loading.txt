Mục tiêu: Khi Exchange kết thúc (ExchangeDone), mỗi bên biết LSA nào còn thiếu
  trong LSDB của mình. Bên thiếu (Loading state) gửi LSR yêu cầu LSA → nhận
  LSU → cài vào LSDB → gửi LSAck. Khi hết thiếu → LoadingDone → Full.

Lưu ý scope dự án (tra trong docs/plan thinking/):
  - P2P only → mỗi interface có đúng 1 neighbor (cấp phát tĩnh)
  - Single-area (backbone 0.0.0.0)
  - Router-LSA only (type=1), không có Network/Summary/AS-external-LSA
  - Không xác thực (AuType=0), checksum luôn 0 (dự án bỏ qua validate checksum)
  - Interface MTU = 0 (bỏ qua trên P2P)
  - Timer rút gọn: RxmtInterval = 0.5s (so với 5s chuẩn)

NeighborData (dùng cho cả 1b1 và 1b2 — không thay đổi, P2P cấp phát tĩnh)
├── state: OspfNeighborState (Loading=6, Full=7)
├── linkStateRequestList: vector<LSAHeader>
│   Danh sách LSA header còn thiếu so với neighbor.
│   Được xây ở 1b1 (Exchange: DD → so sánh LSDB → add vào nếu thiếu).
│   1b2: gửi LSR từ đầu list (giữ nguyên list để retransmit),
│        truncate (xóa) các LSA đã nhận khi LSU đến.
│   Khi list rỗng → LoadingDone → Full.
├── linkStateRetransmissionList: vector<LSARequest>
│   Dùng trong 1c (Flooding) để retransmit LSA chưa ACK.
│   1b2 không ghi vào list này (Section 10.7: "should NOT be placed on
│   the Link state retransmission list").
├── rxmtTimer: cMessage*
│   Chung với 1b1 (DD retransmit). 1b2 dùng cho LSR retransmit.
│   Cancel khi kết thúc Loading.
├── isMaster, ddSequenceNumber: Giữ nguyên từ 1b1 (cần cho duplicate DD
│   detection trong Loading/Full — Section 10.6)
├── lastDdOptions, lastDdIMs, optionsNeighbor: Như trên
└── inactivityTimer: Chung với 1a

linkStateRequestData (class xử lý LSR)
├── requests: vector<LSARequest>
├── sendLSR()  — gửi LSR (Section 10.9 + A.3.4)
└── processLSR() — xử lý LSR nhận (Section 10.7), trả về LsrResult

linkStateUpdateData (class xử lý LSU)
├── numberOfLSA: uint32_t
├── LSAs: vector<LSA>
├── sendLSU()  — gửi LSU (Section 13)
└── processLSU() — xử lý LSU nhận (Section 13), trả về LsuResult

linkStateAcknowledgementData (class xử lý LSAck)
├── data: vector<LSAHeader>
├── sendLSAck() — gửi LSAck (Section 13.5)
└── processLSAck() — xử lý LSAck nhận (Section 13.7) — dùng trong 1c

LsrResult (struct kết quả processLSR)
├── valid: bool (false → BadLSReq)
├── badLSReq: bool (true → handleMessage xử lý state ExStart)
└── lsus: vector<LSA> (các LSA cần gửi về, để handleMessage gọi sendLSU)

LsuResult (struct kết quả processLSU)
├── valid: bool (false → drop gói)
├── loadingDone: bool (true → state = Full)
├── lsasInstalled: int (số LSA mới cài vào LSDB)
└── scheduleSPF: bool (true → schedule SPF calculation)

[Flow] linkStateRequestData::sendLSR(nbr, ifIndex, routerId, mod)
────────────────────────────────────────────────────────────────────
Gửi Link State Request packet (Section 10.9 + A.3.4).
KHÔNG đụng timer — handleMessage lo.

│
├── 1. Kiểm tra linkStateRequestList
│   └── Nếu rỗng → không gửi (LoadingDone sẽ xảy ra qua exchangeDone path)
│
├── 2. Lấy các LSARequest từ đầu list
│   └── Section 10.9: "sends the neighbor the beginning of the Link state
│       request list, packaged in a Link State Request packet"
│       ⚠ Có thể gửi nhiều request trong 1 LSR (tối đa phù hợp MTU,
│         dự án bỏ qua MTU → có thể gửi tất cả trong 1 LSR)
│       └── [Loop] Duyệt linkStateRequestList
│           └── Mỗi phần tử → 1 LSARequest{ type, linkStateId, advRouter }
│               └── put32(type), put32(linkStateId), put32(advRouter)
│
├── 3. Đóng gói LSR body: put32(type) + put32(linkStateId) + put32(advRouter)
│       cho mỗi item từ đầu linkStateRequestList
│       ⚠ KHÔNG xóa item khỏi linkStateRequestList ở bước này.
│         Các item được giữ lại trong list để retransmit nếu cần.
│         (Section 10.9: "LSAs on the Link state request list that have been
│          requested, but not yet received, are packaged ... for retransmission
│          at intervals of RxmtInterval")
│         Chúng chỉ bị xóa (truncated) khi nhận được LSU — Section 10.9:
│         "When the neighbor responds ... the Link state request list is truncated"
│
└── 4. OspfMess::send(3, body, routerId, 0, ifIndex, mod)


[Flow] linkStateRequestData::processLSR(hdr, data, iface, routerLSAs)
───────────────────────────────────────────────────────────────────────
Xử lý Link State Request packet nhận được (Section 10.7 + A.3.4).
KHÔNG đụng timer — handleMessage lo.
Trả về LsrResult.

│
├── 1. Parse LSR body
│   └── [Loop] Đọc đến hết data
│       └── Mỗi lần: get32 → LS type, get32 → linkStateId, get32 → advRouter
│           → 1 LSARequest
│
├── 2. [Loop] Với mỗi LSARequest:
│   ├── Tra LSDB: tìm trong routerLSAs[]
│   │   └── So khớp (type == 1, linkStateId == id, advertisingRouter == advR)
│   │       │
│   │       ├── [Tree] Tìm thấy?
│   │       │   ├── CÓ → copy LSA vào result.lsus
│   │       │   └── KHÔNG → result.badLSReq = true → return result NGAY
│   │       │       (Section 10.7: "If an LSA cannot be found ... BadLSReq")
│   │       │       ⚠ Dừng xử lý ngay khi gặp lỗi đầu tiên (Section 10.7)
│   │
│   ├── [note] LS type validation:
│   │   Dự án chỉ có type=1 (Router-LSA). Nếu request type khác → BadLSReq
│   │   (Section 10.7: "Each LSA specified ... should be located")
│   │
│   └── [note] Section 10.7: "These LSAs should NOT be placed on the
│       Link state retransmission list"
│       → Không thêm vào linkStateRetransmissionList
│
└── 3. result.valid = !result.badLSReq → return result


[Flow] linkStateUpdateData::processLSU(hdr, data, iface, area)
────────────────────────────────────────────────────────────────
Xử lý Link State Update packet nhận được (Section 13 steps 1-8).
KHÔNG đụng timer — handleMessage lo.
Trả về LsuResult.

│
├── 1. Parse LSU body (Section A.3.5)
│   ├── get32 → numberOfLSAs
│   └── [Loop] numberOfLSAs lần:
│       └── Parse 1 LSA: header (20 byte) + body (phụ thuộc length)
│           ├── get16 → age, get8 → options, get8 → type
│           ├── get32 → linkStateId, get32 → advertisingRouter
│           ├── get32 → sequenceNumber, get16 → checksum, get16 → length
│           ├── Đọc body = còn lại length-20 byte
│           │   └── type 1 (Router-LSA):
│           │       ├── get8 → flags, get8 → zero, get16 → numLinks
│           │       └── [Loop] numLinks lần:
│           │           ├── get32 → linkID, get32 → linkData
│           │           ├── get8 → type, get8 → numTOS, get16 → metric
│           │           └── [Loop] numTOS lần: get8 → tos, get8 → zero,
│           │               get16 → tosMetric
│           └── Lưu vào vector<LSA> lsas
│
├── 2. [Loop] Với mỗi LSA trong lsas — Section 13 steps (1)-(8)
│   │
│   ├── (1) Validate LS checksum (Section 13)
│   │   └── Dự án bỏ qua → luôn pass
│   │
│   ├── (2) LS type unknown?
│   │   └── type==1 (Router-LSA) → pass. type khác → discard + continue
│   │
│   ├── (3) AS-external-LSA trong stub?
│   │   └── Area backbone, non-stub → luôn pass
│   │
│   ├── (4) MaxAge + no DB copy + no neighbor Exchange/Loading?
│   │   └── age=MaxAge? AND db lookup == null AND no neighbor ≥ Exchange?
│   │       → add to result.ackHeaders + discard + continue
│   │       (Dự án LSA mới, age=0 → không vào case này)
│   │
│   ├── (5) DB không có hoặc received newer:
│   │   └── DB copy == null OR isNewer(received, dbCopy)
│   │       │
│   │       ├── (5a) MinLSArrival check — dự án bỏ qua
│   │       ├── (5b) Flood ra neighbor ≥ Exchange (gọi floodLSA)
│   │       ├── (5c) Xóa DB copy cũ khỏi retransmission lists
│   │       ├── (5d) Install into LSDB:
│   │       │   ├── Tìm trong area.routerLSAs[] (so advRouter)
│   │       │   ├── Đã có? → replace (xóa cũ, push mới)
│   │       │   ├── Chưa có? → push vào area.routerLSAs
│   │       │   └── result.lsasInstalled++, result.scheduleSPF = true
│   │       ├── (5e) ACK: add LSA header vào result.ackHeaders
│   │       ├── (5f) Self-originated? — dự án bỏ qua (xử lý sau)
│   │       │
│   │       └── [ACTION SPECIFIC TO LOADING] Xóa LSA khỏi
│   │           linkStateRequestList nếu có
│   │           └── (Chỉ khi LSA này đang trong request list)
│   │
│   │   └── (6) DB tồn tại, received không mới hơn (cũ/bằng),
│   │       VÀ LSA còn trong linkStateRequestList của sending neighbor?
│   │       → result.badLSReq = true → dừng xử lý LSU ngay
│   │       (Section 13 (6): "an error has occurred in the Database
│   │        Exchange process")
│   │       ⚠ Ở đây không cần phân biệt "cũ hơn" hay "bằng nhau".
│   │         Nếu neighbor đã gửi LSA mà request list của nó vẫn còn LSA đó,
│   │         tức là neighbor mong muốn nhận bản mới hơn từ ta → có lỗi.
│   │
│   │   └── (7) Same instance (duplicate — so sánh seqNum + checksum)
│   │       (Section 13 (7))
│   │       ├── (7a) Trong retransmission list của sending neighbor?
│   │       │   └── CÓ → implicit ACK: xóa khỏi list
│   │       └── (7b) ACK: add header vào result.ackHeaders
│   │
│   │   └── (8) DB copy mới hơn received (còn lại)
│   │       (Section 13 (8))
│   │       └── Gửi DB copy về neighbor (thêm vào lsusToSend)
│   │           (Section 13: "send the database copy back",
│   │            không vào retransmission list, không ACK)
│   │
├── 3. result.loadingDone = linkStateRequestList.empty()
│   └── (Chỉ set khi nhánh gọi là neighbor đang Loading)
│
└── 4. Return result

================================================================================
LƯU Ý QUAN TRỌNG VỀ LOOP VÀ ĐIỀU KIỆN KẾT THÚC
================================================================================

1. **Vòng lặp gửi LSR (1b2.A Kích hoạt 1):**
   - Mỗi lần gửi LSR: lấy đầu linkStateRequestList → gửi (giữ nguyên list)
   - Mỗi lần nhận LSU: truncate list — xóa các LSA đã nhận khỏi list
     (Section 10.9: "the Link state request list is truncated")
   - → list chỉ ngắn đi khi nhận được LSU
   - Điều kiện kết thúc: linkStateRequestList.empty() → LoadingDone → Full
   - ⚠ Section 10.9: "at most one Link State Request packet outstanding"
     → KHÔNG gửi LSR mới nếu chưa nhận LSU cho LSR trước

2. **Retransmit loop (1b2.A Kích hoạt 2 — rxmtTimer):**
   - Loading: retransmit LSR mỗi RxmtInterval nếu chưa nhận LSU
   - Điều kiện kết thúc: nhận được LSU (1b2.B cancel timer)
     HOẶC neighbor state thay đổi (không còn Loading)

3. **Loop xử lý LSA trong LSU (1b2.B):**
   - Mỗi LSU có thể chứa nhiều LSA (Section 13)
   - Duyệt từng LSA → validate → so DB → install/ACK/discard
   - Điều kiện kết thúc: hết số LSA trong LSU packet

4. **Loop xử lý LSR request items (1b2.C):**
   - Mỗi LSR có thể chứa nhiều LSARequest
   - Duyệt từng request → tra DB → copy vào LSU body
   - Điều kiện kết thúc: hết số requests trong LSR
     HOẶC gặp lỗi (BadLSReq → dừng ngay, Section 10.7)

5. **Song song giữa các neighbor:**
   - Mỗi interface P2P có 1 neighbor riêng, mỗi neighbor có thể
     đang ở Loading state độc lập
   - 1b2.A/B/C chạy song song cho mỗi neighbor
   - Không có xung đột vì mỗi bộ linkStateRequestList là riêng

================================================================================
ĐẦU RA MONG ĐỢI SAU KHI 1b2 HOÀN TẤT
================================================================================

1b2 hoạt động per-adjacency (mỗi neighbor độc lập).
1b2 kết thúc trên từng adjacency khi neighbor chuyển sang Full(7).
Có 2 kịch bản:

  **Kịch bản A: linkStateRequestList rỗng ngay từ ExchangeDone**
    → Không vào Loading → Full ngay (1b1 kết thúc ở trạng thái Full)
    (Trường hợp LSDB 2 bên đồng bộ hoàn toàn — không thiếu LSA nào)

  **Kịch bản B: linkStateRequestList không rỗng → Loading → Full**
    → 1b2 chạy: gửi LSR → nhận LSU → cài LSDB → Full

┌──────────────────────────────────────────────────────────────────────────────┐
│              KẾT QUẢ 1b2 — Loading                                          │
├───────────────────────────────────────┬──────────────────────────────────────┤
│ Thành phần                            │ Giá trị                             │
├───────────────────────────────────────┼──────────────────────────────────────┤
│ Interface.state                       │ PointToPoint (3) — không đổi         │
│ Neighbor.state                        │ Full (7)                            │
│ Neighbor.isMaster                     │ Giữ nguyên từ 1b1 — không đổi       │
│ Neighbor.ddSequenceNumber             │ Giữ nguyên (chỉ dùng cho DD         │
│                                       │ duplicate detection trong Full)      │
├───────────────────────────────────────┼──────────────────────────────────────┤
│ Neighbor.databaseSummaryList          │ Đã clear (hoặc không dùng nữa)       │
│ Neighbor.linkStateRequestList         │ RỖNG (đã được xóa toàn bộ)          │
│ Neighbor.linkStateRetransmissionList  │ Rỗng (chưa dùng — chờ 1c)           │
├───────────────────────────────────────┼──────────────────────────────────────┤
│ rxmtTimer (per neighbor)              │ Đã cancel                            │
│ inactivityTimer                        │ Đang chạy (reset mỗi Hello)         │
├───────────────────────────────────────┼──────────────────────────────────────┤
│ LSDB (area.routerLSAs)                │ ĐÃ CÓ THÊM LSA MỚI                  │
│                                       │ (các LSA kéo về từ neighbor)         │
│                                       │ — CỦA CÁC ROUTER ĐÃ ĐỒNG BỘ          │
│                                       │   TRỰC TIẾP (chưa flood toàn area)   │
│                                       │ — NHƯNG CHỈ CÓ STUB LINKS            │
│                                       │ (chưa có P2P links vì chưa originate)│
├───────────────────────────────────────┼──────────────────────────────────────┤
│ RoutingTable                          │ RỖNG (chưa SPF)                     │
│ SPF vertices                          │ RỖNG (chưa tính)                    │
└───────────────────────────────────────┴──────────────────────────────────────┘

Ví dụ với mạng 4 router (tiếp nối từ 1b1):
         R1 ─── R2
          \    /
           R4
           │
           R6

LSDB TRƯỚC 1b2 (sau 1b1, trước Loading):
  R1: { LSA-R1(stub) }             ← chỉ có LSA của self
  R2: { LSA-R2(stub) }             ← chỉ có LSA của self
  R4: { LSA-R4(stub) }             ← chỉ có LSA của self
  R6: { LSA-R6(stub) }             ← chỉ có LSA của self

linkStateRequestList (sau ExchangeDone — mỗi neighbor biết LSA nào thiếu):
  Trên R1:
    neighbor R2: requestList = [LSA-R2]    (thiếu LSA của R2)
    neighbor R4: requestList = [LSA-R4]    (thiếu LSA của R4)
  Trên R2:
    neighbor R1: requestList = [LSA-R1]    (thiếu LSA của R1)
    neighbor R4: requestList = [LSA-R4]    (thiếu LSA của R4)
  Trên R4:
    neighbor R1: requestList = [LSA-R1]    (thiếu LSA của R1)
    neighbor R2: requestList = [LSA-R2]    (thiếu LSA của R2)
    neighbor R6: requestList = [LSA-R6]    (thiếu LSA của R6)
  Trên R6:
    neighbor R4: requestList = [LSA-R4]    (thiếu LSA của R4)

Loading trên R1 (với neighbor R2 và R4):
  ┌─────────────────────────────────────────────────────────────────┐
  │ R1→R2: gửi LSR{ LStype=1, linkStateId=R2, advRouter=R2 }      │
  │ R2→R1: gửi LSU{ LSA-R2(stub) }                                 │
  │ R1: cài LSA-R2 vào LSDB, gửi LSAck                             │
  │ R1→R2: linkStateRequestList rỗng → LoadingDone → Full(R2)      │
  │                                                                  │
  │ R1→R4: gửi LSR{ LStype=1, linkStateId=R4, advRouter=R4 }      │
  │ R4→R1: gửi LSU{ LSA-R4(stub) }                                 │
  │ R1: cài LSA-R4 vào LSDB, gửi LSAck                             │
  │ R1→R4: linkStateRequestList rỗng → LoadingDone → Full(R4)      │
  └─────────────────────────────────────────────────────────────────┘

LSDB SAU 1b2 (tất cả neighbor Full, nhưng CHỈ stub links):
  R1: { LSA-R1(stub), LSA-R2(stub), LSA-R4(stub) }
  R2: { LSA-R1(stub), LSA-R2(stub), LSA-R4(stub) }
  R4: { LSA-R1(stub), LSA-R2(stub), LSA-R4(stub), LSA-R6(stub) }
  R6: { LSA-R4(stub), LSA-R6(stub) }

  ⚠ LƯU Ý: LSDB vẫn CHỈ có stub links. P2P links chỉ xuất hiện
    sau 1c (originate lại Router-LSA khi có neighbor Full).
    → R1 chưa biết R2-R4 kết nối thế nào, R6 chưa biết R1 và R2.
    → SPF chưa thể tính đúng (thiếu cạnh P2P).
    → Chỉ sau 1c (originate + flood) LSDB mới đồng bộ hoàn toàn.

Điều kiện để chuyển sang 1c (Originate + Flood):
  - Có ít nhất 1 neighbor Full(7) — originate Router-LSA để thêm P2P links
  - (Section 12.4 Event (4): "One of the neighboring routers changes to/from
    the FULL state. This may mean that it is necessary to produce a new
    instance of the router-LSA.")
  - ⚠ Không cần đợi tất cả neighbor Full. Mỗi lần có neighbor chuyển Full
    là một lần originate (có thể bị MinLSInterval giới hạn tần suất).
