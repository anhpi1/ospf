================================================================================
1b1 — ExStart + Exchange (Thương lượng Master/Slave + Trao đổi LSA Header)
  Section 10.3 (Neighbor state machine — events NegotiationDone, ExchangeDone,
                SeqNumberMismatch)
  10.6 (Receiving Database Description Packets)
  10.8 (Sending Database Description Packets)
  A.3.3 (DD packet format)
================================================================================

Mục tiêu: Từ hai neighbor bidirectional (2Way), form adjacency qua 2 bước:
  ExStart  — thương lượng master/slave + DD sequence number
  Exchange — trao đổi danh sách LSA header để mỗi bên biết LSA nào còn thiếu

Lưu ý scope dự án (tra trong docs/plan thinking/):
  - P2P only → mỗi interface có đúng 1 neighbor (cấp phát tĩnh)
  - Single-area (backbone 0.0.0.0)
  - Router-LSA only (type=1), không có Network/Summary/AS-external-LSA
  - Không xác thực (AuType=0), checksum luôn 0
  - Interface MTU = 0 (bỏ qua trên P2P)

CHI TIẾT: CẤU TRÚC DỮ LIỆU SỬ DỤNG (đã có sẵn trong ospf_struct.h)
===============================================================================

NeighborData (mỗi interface có 1, cấp phát tĩnh)
├── state:        OspfNeighborState (ExStart=4, Exchange=5, Loading=6, Full=7)
├── isMaster:     unsigned int (1 = master, 0 = slave)
├── ddSequenceNumber: uint32_t (số thứ tự DD hiện tại — đang gửi hoặc vừa nhận)
├── lastDdOptions: uint8_t (Options từ gói DD cuối, dùng duplicate detection)
├── lastDdIMs:     uint8_t (I+M+MS bits từ gói DD cuối, dùng duplicate detection)
├── optionsNeighbor: uint8_t (Neighbor Options — lưu từ quá trình ExStart, dùng validate)
│   ⚠ Không có "last received DD seq" riêng. Cần khi implement:
│      - Master: lưu ddSeq trước khi increment, hoặc
│      - Dùng ddSequenceNumber + trạng thái isMaster để suy ra
├── databaseSummaryList: vector<LSAHeader> (toàn bộ LSA header LSDB khi vào Exchange)
├── linkStateRequestList: vector<LSAHeader> (LSA cần kéo về — chờ 1b2)
├── linkStateRetransmissionList: vector<LSARequest> (LSA đã gửi chờ ACK — dùng sau)
├── rxmtTimer:    cMessage* (retransmit timer cho DD/LSR)
└── inactivityTimer: cMessage* (chung với 1a)

DdResult (struct kết quả processDD)
├── valid:               bool (false → drop gói)
├── negotiationDone:     bool (NegotiationDone event → chuyển Exchange)
├── exchangeDone:        bool (ExchangeDone event → chuyển Loading/Full)
├── shouldSendDD:        bool (cần gửi DD ngay: Slave response hoặc Master poll mới)
└── neighborStateChanged: bool (state changed → handleMessage xử lý timer)

LSAHeader (dùng trong databaseSummaryList và DD body)
├── age:            uint16_t
├── options:        uint8_t
├── type:           uint8_t (luôn 1 — Router-LSA trong dự án)
├── linkStateId:    uint32_t
├── advertisingRouter: uint32_t
├── sequenceNumber: int32_t
├── checksum:       uint16_t
└── length:         uint16_t

databaseDescriptionData (class xử lý DD)
├── interfaceMTU:   uint16_t
├── options:        uint8_t
├── flags:          uint8_t (I, M, MS bits)
├── ddSequenceNumber: uint32_t
├── lsaHeaders:     vector<LSAHeader> (các LSA header trong body DD)
├── sendDD()        — gửi DD (Section 10.8 + A.3.3)
└── processDD()     — xử lý DD nhận (Section 10.6), trả về DdResult

CHI TIẾT TỪNG HÀM

[Flow] databaseDescriptionData::sendDD(ifIndex, state, routerId, mod)
────────────────────────────────────────────────────────────────────────
Gửi DD packet theo trạng thái neighbor (Section 10.8 + A.3.3).

│
├── 1. Xác định flags (I, M, MS) dựa vào state
│   │
│   ├── [Tree] nbr->state == ExStart:
│   │   └── flags = I | M | MS (DD rỗng, I=1, M=1, MS=1)
│   │       Section 10.8: "In state ExStart the router sends empty
│   │       Database Description packets, with I, M and MS bits set."
│   │
│   └── [Tree] nbr->state == Exchange:
│       ├── I = 0 (không còn Init)
│       ├── M = ? (còn LSA header để gửi không?)
│       │   └── [Loop/Recursion] Duyệt databaseSummaryList
│       │       ├── Còn LSA chưa gửi → M = 1 (More)
│       │       └── Hết → M = 0 (đây là DD cuối)
│       └── MS = isMaster (1 nếu master, 0 nếu slave)
│
├── 2. Xây DD body (8 byte + N * 20 byte LSA header)
│   ├── put16 — InterfaceMTU (0 cho P2P, không cần MTU check)
│   ├── put8  — Options (OPT_E: ExternalRoutingCapability)
│   ├── put8  — flags (I | M | MS)
│   ├── put32 — ddSequenceNumber
│   └── [Loop] Nếu state == Exchange:
│       └── Gửi 1 hoặc nhiều LSA header từ databaseSummaryList
│           (lấy từ đầu list, đánh dấu đã gửi)
│           Mỗi LSA header = 20 byte
│
└── 3. OspfMess::send(2, body, routerId, 0, ifIndex, mod)

Lưu ý về M-bit trong Exchange (Section 10.8):
  - Master: gửi DD poll, M=1 nếu còn LSA, M=0 nếu hết
  - Slave: response với M=1 nếu còn, M=0 nếu hết
  - ExchangeDone: cần cả 2 chiều M=0
    (Section 10.6: Master thấy ExchangeDone khi nó đã gửi hết
     AND gói vừa accept có M=0; Slave thấy khi cả 2 chiều M=0)

===============================================================================
LƯU Ý QUAN TRỌNG VỀ LOOP VÀ ĐIỀU KIỆN KẾT THÚC
===============================================================================

1. **Vòng lặp gửi DD (Master, Exchange state):**
   - Master gửi DD poll → chờ Slave ACK (echo DD seq)
   - Nếu Slave không ACK trong RxmtInterval → rxmtTimer cháy → retransmit
   - Điều kiện kết thúc: Master đã gửi hết databaseSummaryList
     VÀ nhận được DD từ Slave có M-bit = 0
     → ExchangeDone

2. **Vòng lặp Slave response:**
   - Slave gửi DD mỗi khi nhận poll hợp lệ từ Master
   - Điều kiện kết thúc: Slave đã gửi hết databaseSummaryList
     VÀ gói nhận từ Master có M-bit = 0
     → ExchangeDone (Slave thấy trước Master)

3. **Retransmit loop (rxmtTimer):**
   - ExStart: retransmit DD rỗng I+M+MS mỗi RxmtInterval
   - Exchange (Master): retransmit DD cuối mỗi RxmtInterval
   - Exchange (Slave): KHÔNG retransmit (chỉ response)
   - Điều kiện kết thúc: state change ra khỏi ExStart/Exchange
     → cancel rxmtTimer

4. **SeqNumberMismatch recovery:**
   - Gặp lỗi → restart từ ExStart
   - xóa 3 list → ddSeq++ → isMaster=1 → gửi DD rỗng I+M+MS
   - Điều kiện kết thúc loop lỗi: NegotiationDone → Exchange thành công
     (Nếu lỗi liên tục → infinite loop về mặt lý thuyết,
      trong thực tế P2P không có lỗi vì không có thay đổi Options giữa chừng)

ĐẦU RA MONG ĐỢI SAU KHI 1b1 HOÀN TẤT
===============================================================================

1b1 có 2 mốc quan trọng:
  - **Trong khi Exchange đang chạy** (DD packets đang trao đổi, chưa ExchangeDone):
    neighbor.state == Exchange(5)
  - **Sau khi ExchangeDone** (kết thúc trao đổi DD header):
    neighbor.state == Loading(6) hoặc Full(7) tùy linkStateRequestList

Bảng dưới mô tả trạng thái **SAU KHI ExchangeDone** (đầu ra cuối của 1b1):

│              KẾT QUẢ 1b1 — ExStart + Exchange                           │

Ví dụ với mạng 4 router:
         R1 ─── R2
          \    /
           R4
           │
           R6

Sau Hello (1a), mỗi router có neighbor ở 2Way.
Sau 1b1, tùy Router ID lớn/nhỏ, một bên làm master:

  Trên cặp R1(1)-R2(2):
    R1: isMaster=0 (slave, vì RouterID R2 > R1)
    R2: isMaster=1 (master)
    ddSequenceNumber: R1 dùng seq của R2, R2 tăng dần
    Cả 2 biết nhau có LSA gì → linkStateRequestList ở mỗi bên

  Trên cặp R1(1)-R4(4):
    R1: isMaster=0, R4: isMaster=1

  Trên cặp R2(2)-R4(4):
    R4: isMaster=1, R2: isMaster=0

  Trên cặp R4(4)-R6(6):
    R4: isMaster=0 (slave, vì RouterID R6 > R4)
    R6: isMaster=1 (master)

Kết quả trên R4 (RouterID=4) sau 1b1:
  - Có 3 adjacency đang Exchange với R1, R2, R6
  - databaseSummaryList: copy LSA header của R4 (type=1, id=4, adv=4)
    → gửi cho cả 3 neighbor
  - linkStateRequestList mỗi neighbor:
    - R4 vs R1: request LSA header của R1 (chưa có trong LSDB R4 trừ LSA self)
      → linkStateRequestList của R1's neighbor = [LSA{type=1, id=1, adv=1}]
    - R4 vs R2: request [LSA{type=1, id=2, adv=2}]
    - R4 vs R6: request [LSA{type=1, id=6, adv=6}]

Điều kiện để chuyển sang 1b2 (Loading):
  - ExchangeDone event xảy ra
  - linkStateRequestList KHÔNG rỗng → state = Loading
  - Nếu linkStateRequestList rỗng (cả 2 bên có LSDB giống hệt) → state = Full

Điều kiện để chuyển sang 1c (Originate + Flood):
  - neighbor.state == Full (kết thúc 1b1 nếu không thiếu LSA,
    hoặc sau 1b2 nếu thiếu)
