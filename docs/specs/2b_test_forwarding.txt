2b — TEST FORWARDING (Kiểm tra chuyển tiếp gói dữ liệu)
  RFC 2328 Section 11 (The Routing Table Structure)
  11.1 (Routing table lookup)
  16 (Calculation of the routing table)
  16.8 (Equal-cost multipath)
================================================================================

Mục tiêu: Với routing table đã có từ Phase 2a, kiểm tra khả năng forward
  gói dữ liệu giữa mọi cặp router trong mạng.
  - Mỗi router gửi 1 data packet đến 9 router còn lại
  - Mỗi gói tin được forward qua từng chặng theo routing table
  - Verify: packet đến đúng đích, cost khớp với routing table
  - 10 router × 9 đích = 90 test cases

Lưu ý scope dự án (tra trong docs/plan thinking/):
  - P2P only → forward ra gate index, không cần next-hop IP
  - Single-area → routing table chỉ có intra-area routes
  - Router-ID là 32-bit integer (1-10), dùng làm destination ID và source ID trong data packet
  - Không có client module riêng — router tự sinh test packet (self-message)
  - RoutingTableEntry.nextHop là Router ID (uint32_t), không phải IP
  - Khi nextHop == 0 → không tìm thấy route (unreachable)
  - Topology mesh 10 router, link cost random 1-30
  - ⚠ Giá trị INFINITY cho nextHop: dùng UINT_MAX (calcNextHop trả về UINT_MAX khi không
    tìm thấy). nextHop == 0 KHÔNG phải INFINITY, 0 là Router ID không dùng (1-10).

CHI TIẾT: FORWARD DATA — routing table lookup (Section 11.1, P2P đơn giản hóa)

[Flow] forwardData(msg, ifIndex)
  Input: Mess* msg (payload[0-3] = dest Router ID, payload[4-7] = src Router ID),
         ifIndex (gate nhận, -1 nếu từ local)
  Output: void (gửi tiếp hoặc delete)
│
├── 1. Parse destination + source
│   ├── dest   = (payload[0] << 24) | (payload[1] << 16) |
│   │           (payload[2] << 8) | payload[3]
│   ├── srcId  = (payload[4] << 24) | (payload[5] << 16) |
│   │           (payload[6] << 8) | payload[7]
│   │
│   └── [Tree] dest == routerId ?
│       ├── YES → packet đến đích
│       │   ├── [Verify B] expectedCost = tìm routing table entry cho srcId
│       │   │   → ghi log cost + PASS/FAIL
│       │   ├── Ghi log: "2b: Received srcId→self cost=X"
│       │   └── delete msg; return
│       │
│       └── NO → cần forward tiếp
│
├── 2. [Loop] Routing table lookup (Section 11.1)
│   │
│   └── Duyệt RoutingTable[]:
│       │
│       ├── [Tree] Tìm entry có destinationType == 'R' (router)
│       │   và destinationId == dest?
│       │   │
│       │   ├── CÓ:
│       │   │   ├── nextHopId = entry.nextHop
│       │   │   ├── cost = entry.cost
│       │   │   └── [ECMP] Nếu có nhiều entry cùng dest (ECMP)?
│       │   │       └── Chọn nextHop đầu tiên (hoặc round-robin — tùy thiết kế)
│       │   │
│       │   └── KHÔNG → unreachable
│       │       ├── Ghi log: "2b: No route to dest, drop"
│       │       └── delete msg; return
│       │
│       └── (Luôn tìm thấy trên P2P single-area topology 10 router — SPF đảm bảo)
│
├── 3. [Loop] Tìm output gate từ nextHop Router ID
│   │
│   └── Duyệt interfaces[]:
│       │
│       └── [Tree] interfaces[i].neighbor.IDNeighbor == nextHopId?
│           │
│           ├── CÓ → gateIndex = i
│           └── KHÔNG → tiếp tục
│               │
│               └── Hết interfaces không tìm thấy → lỗi
│                   ├── Ghi log: "2b: NextHop not directly connected"
│                   └── delete msg; return
│
├── 4. Forward
│   ├── send(msg, "gate$o", gateIndex)
│   └── Ghi log: "2b: Forward srcId→dest via gate[gateIndex]→nextHopId"
│       └── (msg đã được send, không delete — OMNeT++ quản lý)
│
└── [Done] Kết thúc forwardData

[Flow] verifyPacket(srcId, pathLog[])

│

└── Tổng hợp kết quả cho srcId

│    - parse() trả về 0 → đó là data packet (trong môi trường simulation   │
│      chỉ có code của mình chạy, không có OSPF malformed từ bên ngoài)    │
│    - Kiểm tra dynamic_cast<Mess*> để chắc chắn đó là Mess              │
│    ⚠ PHẢI SỬA dòng `if (pktType == 0) { delete msg; return; }` hiện có  │
│      → Thay bằng else-if để data packet rơi xuống nhánh xử lý bên dưới  │
│      Ví dụ cấu trúc mới: if(pktType==1){...} else if(pktType==2){...}   │
│      ... else if(pktType==5){...} else { /* data packet */ }            │
│                                                                          │
│ 4. Test initialization:                                                  │
│    - Thêm cMessage* testTimer trong routerOspf (private)                 │
│    - schedule testTimer ở initialize() hoặc sau khi SPF hoàn tất        │
│    - SPF delay (spfTimer cháy) → testTimer schedule sau 0.5s            │
│    - testTimer cháy → initForwardingTest()                               │
│                                                                          │
│ 5. Giới hạn forwardData:                                                 │
│    - Chỉ forward nếu destination != routerId                             │
│    - Không forward nếu nextHop == 0 (unreachable). ⚠ nextHop == 0 là     │
│      giá trị đặc biệt (Router ID không dùng 1-10), không phải INFINITY.  │
│      calcNextHop dùng UINT_MAX cho "không tìm thấy".                     │
│    - Tìm gate từ interfaces[i].neighbor.IDNeighbor == nextHop            │
│                                                                          │
│ 6. Log mỗi bước forward:                                                 │
│    state->logTransition("2b", "Forward: R1→R5 via gate 2 to R2",        │
│                         simTime().dbl(), ifIndex);                       │
│    Mỗi router ghi log → ghép log toàn mạng → trace được đường đi        │
│                                                                          │
│ 7. Xử lý ECMP cho forwarding test (Section 16.8):                       │
│    - ECMP là tính năng OSPF chuẩn: khi có nhiều đường cùng cost đến     │
│      cùng đích, RFC 2328 cho phép chọn bất kỳ đường nào trong ECMP set  │
│    - Dự án: routing table chỉ lưu 1 nextHop (RoutingTableEntry.nextHop  │
│      là uint32_t, không phải vector). Khi ECMP xảy ra, nextHop là       │
│      predecessor đầu tiên trong SPF — đây là simplification cho test.   │
│    - Khi verify, CHỈ kiểm tra packet đến đúng đích. KHÔNG kiểm tra       │
│      packet đi qua đường cụ thể nào — mọi đường ECMP đều hợp lệ.         │
│      Verify C (đường đi đúng) là tùy chọn, chỉ để debug.                │
│                                                                          │
│ 8. Timer testTimer khai báo trong ospf.h:                                │
│    cMessage* testTimer;     // Timer kích hoạt forwarding test          │
│    void forwardData(Mess* msg, int ifIndex);  // Forward data packet     │
│    void initForwardingTest();                   // Khởi tạo 9 test packet│
│                                                                          │
│ 9. finish() cần cancelAndDelete testTimer nếu chưa cháy                 │
│                                                                          │
│ 10. Thời điểm kích hoạt test:                                            │
│     - initialize: testTimer = nullptr                                    │
│     - Khi spfTimer cháy lần cuối (Phase 2a kết thúc):                   │
│       if (!testTimer) {                                                  │
│           testTimer = new cMessage("testTimer");                         │
│           scheduleAt(simTime() + 0.1, testTimer);  // 0.1s sau SPF     │
│       }                                                                  │
│     - testTimer cháy → initForwardingTest()                             │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
