Mục tiêu: Khi neighbor chuyển Full(7), originate lại Router-LSA bổ sung
  P2P links → flood ra tất cả neighbor để đồng bộ LSDB toàn area.
  Sau đó, mỗi khi nhận LSU chứa LSA mới từ flooding, xử lý Section 13
  (validate → so sánh LSDB → cài đặt → flood tiếp → ACK).
  Khi LSDB thay đổi, schedule SPF để tính lại routing table.

Lưu ý scope dự án (tra trong docs/plan thinking/):
  - P2P only → mỗi interface có đúng 1 neighbor (cấp phát tĩnh)
  - Single-area (backbone 0.0.0.0)
  - Router-LSA only (type=1), không có Network/Summary/AS-external-LSA
  - Không xác thực (AuType=0), checksum luôn 0
  - Interface MTU = 0 (bỏ qua MTU check)
  - Timer rút gọn: RxmtInterval = 0.5s
  - MinLSArrival = 1s (dự án bỏ qua timing → luôn pass)
  - InfTransDelay = 1s (tăng age LSA trước khi flood)
  - MinLSInterval = 5s (tần suất tối đa originate Router-LSA)

===============================================================================
LƯU Ý QUAN TRỌNG VỀ LOOP VÀ ĐIỀU KIỆN KẾT THÚC
===============================================================================

1. **Vòng lặp xây Router-LSA (1c Origination):**
   - Duyệt tất cả InterfaceData trong area
   - Mỗi interface: kiểm tra state → thêm Type 3 (stub) + Type 1 (P2P nếu Full)
   - Điều kiện kết thúc: duyệt hết interfaces
   - ⚠ Mỗi router chỉ tạo 1 Router-LSA, không phải 1 per interface

2. **Vòng lặp flood LSA (1c.D — duyệt interface):**
   - Duyệt tất cả interface trong area
   - Mỗi interface: kiểm tra từng neighbor (P2P chỉ có 1)
   - Điều kiện kết thúc: duyệt hết interface
   - ⚠ LSA được add vào retransmission list NHƯNG chỉ flood ra interface
     khi có ít nhất 1 neighbor cần (Section 13.3(2))

3. **Song song giữa các neighbor:**
   - BẮT BUỘC: khi flood 1 LSA mới (1c.D),
     phải thêm vào retransmission list của MỌI neighbor ≥ Exchange
   - Sau đó gửi LSU riêng ra mỗi interface (P2P: unicast)
   - rxmtTimer per-neighbor: mỗi neighbor có timer riêng
     → mỗi neighbor retransmit độc lập

4. **Loop retransmit (1c.C — rxmtTimer):**
   - Mỗi lần rxmtTimer cháy: duyệt toàn bộ linkStateRetransmissionList
   - Tra LSDB → lấy LSA đầy đủ → xây LSU → gửi
   - Điều kiện kết thúc: list.empty() → cancel timer
   - ⚠ Section 13.6: "several retransmitted LSAs may fit into a single
     Link State Update packet" — có thể batch nhiều LSA trong 1 LSU

5. **Loop xử lý LSU (1c.A — duyệt LSA trong LSU):**
   - Section 13 steps (1)-(8) cho mỗi LSA
   - Điều kiện kết thúc: hết LSA trong LSU packet

6. **Loop xử lý LSAck (1c.B — duyệt ACK trong LSAck):**
   - Mỗi ACK = 1 LSAHeader, so với linkStateRetransmissionList
   - Điều kiện kết thúc: hết ACK trong LSAck packet

7. **Chuỗi phản ứng dây chuyền (Chain reaction):**
   - Router A: neighbor → Full → originate Router-LSA với P2P links
   - Router A: flood LSA mới → Router B, C, ...
   - Router B: nhận LSU → Section 13 (5b) → flood tiếp → Router D, E, ...
   - Router B: Schedule SPF (LSDB thay đổi)
   - → Toàn bộ area dần đồng bộ LSDB
   - Điều kiện kết thúc: tất cả router trong area có cùng LSDB
     (cùng set Router-LSA, cùng P2P links)
     → Không còn LSA mới được originate → không còn flood
     → Tất cả retransmission lists rỗng → rxmtTimers đều cancel
     → SPF timers cháy → routing tables được tính
