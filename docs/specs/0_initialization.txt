================================================================================
0 — INITIALIZATION & INFRASTRUCTURE (Khởi tạo hệ thống OSPF)
  Section 4 (Functional Summary), Section 9.3 (Interface state machine),
  Section 12.4 (Originating LSAs), A.4.2 (Router-LSA format)
================================================================================

Mục tiêu: Khởi tạo toàn bộ cấu trúc dữ liệu OSPF, thiết lập interface,
         tạo Router-LSA ban đầu (stub links), chuẩn bị timer và gửi
         Hello đầu tiên để kickstart Hello Protocol.

Phạm vi: P2P single-area, không DR/BDR, không xác thực, không checksum.
         Chạy ĐÚNG 1 LẦN khi router khởi động (initialize() trong OMNeT++),
         không lặp lại trong suốt vòng đời mô phỏng.

Lưu ý: Phase 0 không xử lý gói tin hay timer — nó là phần "trước khi
       handleMessage() được gọi lần đầu tiên".

[Flow] originateRouterLSA(state)
────────────────────────────────
│
├── Tạo Router-LSA cho area duy nhất (Section 12.4.1)
│
├── Input: OspfRouterState& state
│
├── Output: Cập nhật state.area.routerLSAs[]
│
├── 1. Tạo LSA object mới
│   ├── header = {age:0, opt:OPT_E, type:1, linkStateId:routerID,
│   │            advRouter:routerID, seq:0x80000001, chk:0, len:0}
│   ├── flags = 0 (B=0, E=0, V=0)
│   ├── numLinks = 0 (sẽ đếm sau)
│   └── links = []
│
├── 2. [Loop] Với mỗi interface trong state.interfaces[]
│   │
│   └── [Tree] iface.state ?
│       │
│       ├── == Down → skip
│       │
│       ├── == Loopback → link {type:3, linkID:ip, linkData:0xFFFFFFFF, cost:0}
│       │
│       └── == PointToPoint:
│           ├── [Tree] Nếu neighbor.state == Full (chưa, Phase 0)
│           │   → không thêm Type 1
│           └── Thêm Type 3 stub link:
│               link {type:3, linkID:neighborIP (hoặc 0), linkData:0xFFFFFFFF,
│                      cost:iface.cost}
│
├── 3. Cập nhật numLinks, length
│
└── 4. Thay thế LSA cũ trong LSDB:
    ├── Nếu đã có LSA của router này (cùng advRouter) → thay thế
    └── Chưa có → push_back vào area.routerLSAs[]
        (lần đầu tiên: chưa có → push_back)

Lưu ý: Phase 0 chưa flood LSA. Flood sẽ xảy ra sau khi có neighbor ở
trạng thái Full (Giai đoạn 4 — Flooding). Ở Phase 0, LSA chỉ tồn tại
trong LSDB local.

├──────────────────────────────────┬─────────────────────────────────────────┤
│ Thành phần                       │ Giá trị                                 │
├──────────────────────────────────┼─────────────────────────────────────────┤
│ Router ID                        │ 1..10 (từ tên module r1..r10)           │
├──────────────────────────────────┼─────────────────────────────────────────┤
│ interfaces[].state               │ PointToPoint (3) — tất cả interface     │
│ interfaces[].type                │ 1 (P2P)                                 │
│ interfaces[].helloInterval       │ 10 (giây)                               │
│ interfaces[].routerDeadInterval  │ 40 (giây)                               │
│ interfaces[].cost                │ 1 (mặc định)                            │
│ interfaces[].rxmtInterval        │ 5 (giây)                                │
├──────────────────────────────────┼─────────────────────────────────────────┤
│ interfaces[].neighbor.state      │ Down (0) — tất cả neighbor              │
│ interfaces[].neighbor.IDNeighbor │ 0 (chưa biết)                           │
│ interfaces[].neighbor.inactivityTimer │ nullptr (chưa tạo)                 │
│ interfaces[].neighbor.rxmtTimer      │ nullptr (chưa tạo)                  │
├──────────────────────────────────┼─────────────────────────────────────────┤
│ helloTimer                       │ Đã schedule (lần cháy đầu tiên)         │
│ inactivityTimer (các neighbor)   │ Chưa tạo (sẽ tạo khi nhận Hello)        │
├──────────────────────────────────┼─────────────────────────────────────────┤
│ area.routerLSAs                  │ [1 LSA] — Router-LSA của chính mình     │
│                                  │   + stub links cho mỗi interface        │
│                                  │   + KHÔNG có Type 1 link (chưa Full)    │
│ area.spfVertices                 │ [] — rỗng                              │
├──────────────────────────────────┼─────────────────────────────────────────┤
│ RoutingTable                     │ [] — rỗng (chưa tính SPF)               │
└──────────────────────────────────┴─────────────────────────────────────────┘

Ví dụ với mạng 10 router (theo ospf.ned):
         R1 ─── R2 ─── R3 ─── R8
         │   / │       │       │
         │  /  │       │       │
         │ /   │       │       │
         R4 ─── R5 ─── R9      R10
         │       │
         │       │
         R6      R7

Sau Phase 0, mỗi router có:
- 1 Router-LSA trong LSDB với N stub links (N = số interface của router đó)
  Ví dụ R1: 2 stub links (R1→R2, R1→R4)
  Ví dụ R4: 4 stub links (R4→R1, R4→R2, R4→R5, R4→R6)
- Tất cả interface ở PointToPoint
- Tất cả neighbor ở Down
- Chưa có Type 1 link nào (P2P link chỉ xuất hiện khi neighbor Full)

┌────────────────────────────────────────────────────────────────────────────┐
│ CHUYỂN TIẾP                                                            │
│                                                                         │
│ Sau Phase 0, router bắt đầu vòng đời OSPF:                             │
│ → Hello Protocol (Phase 1a) — gửi/nhận Hello, phát hiện neighbor       │
│ → ExStart (Phase 1b1) — thương lượng Master/Slave                      │
│ → Exchange (Phase 1b2) — trao đổi database summary                     │
│ → Loading (Phase 1c) — tải LSA còn thiếu                               │
│ → Full (Phase 1d) — adjacency established                               │
│ → Flooding & SPF (Phase 2+) — tính toán routing table                  │
└────────────────────────────────────────────────────────────────────────────┘
