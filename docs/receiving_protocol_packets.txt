8.2 Nhận gói tin OSPF (RFC 2328 trang 60-63)
=============================================

Nhận gói OSPF
    │
    ├─A. Kiểm tra IP level (Section 8.2)
    │   ├── IP checksum đúng
    │   ├── IP đích = IP interface hoặc AllSPFRouters/AllDRouters
    │   ├── IP protocol = OSPF (89)
    │   └── Không phải gói tự gửi (source IP != chính mình)
    │
    └─B. Kiểm tra OSPF header (Section 8.2)
        ├── Version = 2
        ├── Area ID: khớp interface nhận (P2P khớp AreaID là đủ)
        │   (hoặc backbone nếu virtual link — bỏ qua, ko dùng)
        ├── AuType (auth type) khớp với area
        ├── Authentication pass
        └── AllDRouters: chỉ chấp nhận nếu interface là DR/BDR
            (P2P bỏ qua)

Giải thích từng bước
======================

Bước A — Kiểm tra IP level
    Các kiểm tra này xảy ra ở tầng IP trước khi gói tin được chuyển lên OSPF.
    Trong mô phỏng OMNeT++, các test này mặc định được OMNeT++ xử lý hoặc
    không cần vì là mô phỏng, nhưng cần biết để khi implement thực tế:

    - IP checksum: đảm bảo gói tin không bị hỏng trên đường truyền.
    - IP đích: phải là địa chỉ của interface nhận (unicast) hoặc multicast
      địa chỉ OSPF (224.0.0.5 AllSPFRouters, 224.0.0.6 AllDRouters).
    - IP protocol: OSPF dùng protocol number 89 (IANA assigned).
    - Tự kiểm tra: Nếu gửi multicast, router không được xử lý gói do chính
      nó vừa gửi ra. Trong OMNeT, loopback không xảy ra nên không cần.

Bước B — Kiểm tra OSPF header
    OSPF header được kiểm tra ngay sau khi IP filter pass. Các mục:

    - Version: phải = 2 (OSPFv2). OSPFv1 (version 1) hiếm gặp và không
      tương thích.

    - Area ID: phải khớp với Area ID của interface nhận. Trên P2P, vì chỉ
      có 1 interface ở đầu kia, chỉ cần so sánh Area ID là đủ. Trên broadcast,
      còn kiểm tra thêm IP nguồn (mask cả 2 bên để xem có cùng subnet).
      RFC ghi rõ P2P bỏ qua bước "mask comparison" (dòng 3062-3065).

    - AuType: kiểu xác thực. Trong dự án này dùng authType=0 (không xác thực),
      nên chỉ cần kiểm tra authType nhận được == 0. Nếu mô phỏng trong
      tương lai thêm auth, sẽ mở rộng ở đây.

    - Authentication: nếu AuType != 0, phải kiểm tra auth data. Trong dự án
      bỏ qua (authType=0).

    - AllDRouters: gói gửi đến 224.0.0.6 chỉ dành cho DR/BDR. P2P không có
      DR/BDR nên bỏ qua. Không gặp trong dự án.

Tóm tắt cho P2P (phạm vi dự án)
=================================
Nhận gói → check IP (bỏ qua trong mô phỏng) → check OSPF header
    → Version == 2?
    → AreaID == iface->areaID?
    → AuthType == 0?
    → pass → forward đến xử lý theo type (Hello, DD, LSR...)
